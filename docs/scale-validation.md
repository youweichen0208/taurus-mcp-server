# 规模与边界验证

本文件记录发布门禁覆盖的资源保护行为。它证明安全上限在压力输入下仍然生效，
但不替代客户在目标 TaurusDB 规格、网络和工作负载上的容量压测。

## CI 中的确定性验证

`npm test` 和 MySQL 8 integration harness 覆盖：

- 200 个并发调度任务下，活动查询数不超过配置上限，所有排队任务最终释放；
- 队列满和等待超时返回 `SERVER_BUSY`，不会无限积压；
- 10,000 行、每行约 4 KiB 的驱动结果被序列化字节预算截断；
- MySQL 返回数百行大字段时，MCP 对外响应仍不超过配置的结果字节上限；
- SQL 超时后销毁连接，超时 mutation 不在未知连接状态上继续提交或回滚；
- 审计 writer 在 200 个并发事件和多次轮转下保持 JSONL 完整、无事件重复或丢失；
- 本地 MySQL 构造临时磁盘 spill、空闲连接堆积和锁等待，诊断链路返回真实证据。

运行方式：

```bash
npm run release:check
```

MySQL harness 由 GitHub Actions 使用独立只读/写入账号执行，配置见
`.github/workflows/ci.yml`。

## 真实环境容量测试

正式客户容量结论至少需要在与生产相同的网络路径和 TaurusDB 规格上记录：

1. 只读查询持续负载、突发负载和队列饱和；
2. 小结果、高行数、大字段/BLOB 和敏感字段脱敏；
3. 数据库慢查询超过 MCP timeout 后的连接回收；
4. 连接池上限、数据库 `max_connections` 余量和多 MCP 进程叠加；
5. 审计磁盘增长、轮转、采集断网恢复和集中存储延迟；
6. MCP 进程 CPU、RSS、事件循环延迟、P50/P95/P99 和错误码分布；
7. TaurusDB 主节点、只读节点及故障切换后的诊断降级行为。

验收报告必须注明版本 SHA、npm integrity、实例规格、数据量、SQL 形态、并发模型、
限额配置、持续时间和原始指标位置。没有这些证据时，只能声称安全边界经过验证，
不能声称达到某个吞吐或并发容量。
